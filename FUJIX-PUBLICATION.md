# FujiX Chromaforge — public source snapshot

This source snapshot is based on upstream [emmertex/chromaforge](https://github.com/emmertex/chromaforge) commit `b8a1b8b1f96020a2bc1efd3d2e89d46cb42498af` plus the local FujiX Rust changes. The source copy came from a shallow Git checkout, whose upstream parent objects were unavailable to the new remote; its **public release branch therefore begins with a fresh snapshot commit** rather than copying a broken, incomplete shallow history. The original upstream commit history remains available at the credited upstream repository. The original project is MIT-licensed with Apache-2.0 exceptions for `crates/segment` and `crates/fetch`. Preserve `LICENSE`, `NOTICE`, and `assets/ATTRIBUTION.md` and review transitive dependencies before packaging software. No original installer or native binary is included.

The editor adds an X100VI recipe/draft interface, locally staged C1–C7 assignments and read-only camera capability helpers. The 101 privately saved creator-sourced recipes are replaced with an empty schema-compatible catalog. Import your own legally redistributable records or create drafts. **Physical X100VI camera recipe write, restore, and readback are NOT proven**. The slot UI cannot be described as physically programmed camera settings.

**Installed parity:** A November 5 native build was installed on the user's machine, but newer November 8 photo-culling edits were not built into that installed application after a disk-space failure. This repository contains those newer edits and is thus NOT binary-identical to the currently installed application. Native build/test and graphical QA are required. No camera write or hardware test was run during staging.

This repository carries source code rather than a verified release binary. Build with Cargo as documented upstream, respecting its native dependencies and available disk space. For historical source attribution and full commit history, consult the upstream Git repository and its tagged releases. GitHub publication does not prove that the current app binary has been rebuilt or its camera features validated.

**Workflow scope:** The upstream `.github/workflows/` GitHub Actions definitions are intentionally omitted from this source snapshot. The connected Git credential does not have GitHub's `workflow` permission; publishing those files is rejected by GitHub. The app source, Rust workspace, license notices and build documentation remain. Maintainers can restore workflows from upstream using credentials explicitly authorized for workflow changes.
